### 当前源码中的优化机会

以下是 2026-11-04 最初调查时的源码快照与候选，不代表后续代码仍保持原样；按前台常驻问题优先，编辑与订阅更新峰值另列。具体实施、对照与未完成事项见下方 [首页与代理状态优化](#2026-11-04-首页与代理状态优化实施)。

1. **首页和壳层对象按需创建**：[首页](../../../qml/features/home/home_page.qml)无条件创建多张卡片，[网络工具](../../../qml/features/home/network_tools.qml)的 IP 与网站区块只以 `visible` 隐藏，隐藏不等于销毁子对象；[主窗口](../../../qml/main.qml)也预建对话框及宽/窄导航。可先用 QML 对象/内存剖面定位成本，再将禁用区块、关闭的较重弹层按需 `Loader`，并评估在保留滚动几何的前提下延后创建首屏外区域；Loader 自身有成本，只处理经测量较重的子树。**默认 IP 和网站均为开启**，因此仅为“关闭设置”添加 Loader 不会降低默认首页基线；要减少默认占用，必须测量并优化默认可见内容或首屏外创建策略。保留交互状态、动作运行时机、键盘焦点与无障碍；编辑或运行中的功能不能因滚出视口而丢失。页面切换 Loader 已存在，不应当作新优化。
2. **代理状态从全量投影改为按需**：[UiState](../../../src/presentation/ui_state.cpp)在节点、组或延迟变化后为全部节点/组重建 `proxyStates_`；[首页控件](../../../qml/features/home/home_proxy_controls.qml)即使下拉未打开也对主组所有成员生成状态、标签和描述数组。优先评估轻量变更版本/通知与当前项状态，打开列表后仅由可见 delegate 按需获取，或用稳定 ID 的角色模型。已有节点池和下拉列表可见 delegate 惰性模型，不重复实现；保留嵌套组、不同测试目标、原始选择值和无障碍语义。是否发生 QML/JS 深复制须用剖面确认，不能把 Qt 隐式共享值一律视为独立深拷贝。
3. **业务数据所有权与生命周期**：[运行通道](../../../src/application/runtime_update.h)的 `groups`、`nodes`、`delays`、`delay_details` 非页面 scoped；[UiState](../../../src/presentation/ui_state.cpp)同时持有 JSON 基线、QVariant 列表/映射和派生状态，卸载页面或窗口不等于清空这些业务数据。评估单一权威数据源、首页必需摘要及页面详情按需投影，隐藏时回收可重建的展示派生值，恢复时按需求重建，并按代次防止过期结果复活；首页仍需主组、成员及选择，不能简单清空全部数据。[controlState](../../../src/application/desktop_runtime.cpp)每次构造 `features.delayTimes`，可评估数据变化时缓存/复用；该字段属于[现有契约](../../design/03-数据模型与接口契约.md)，未经消费者及契约核对不能删除。
4. **内核控制层刷新峰值**：[DesktopRuntime](../../../src/application/desktop_features.cpp)在有代理需求时约每 5 秒刷新；[EngineSession](../../../src/infra/core/engine_session.cpp)依次读取 `/proxies` 和 `/providers/proxies`，前者的对象在后者处理期间保留并合并。先记录响应解析和发布阶段的峰值及重叠生命周期，再评估尽早投影必要字段、缩短临时结果寿命并避免无变化时重复派生。现有 `groupsPending_`/`groupsQueued_`、读取上限和 latest mailbox 已限制并发/队列，不应断言请求无限堆积；必须保留动态 provider、自动组、身份安全、失败留旧和恢复语义。此项主要面向刷新峰值，不能据此解释无内核的托盘试验；不修改 Mihomo 本体。
5. **场景化大文本和配置解析**：[编辑器](../../../qml/components/profile_editor.qml)在订阅页即构造，打开后整份文本进入 TextArea；历史 512 KiB 单行草稿有很高的提交峰值，但不能当作普通空闲前台根因。先确认当前版本真实曝光下的大文本复现，再评估弹层惰性创建及更合适的可视范围/分块编辑方案，保留全文、撤销、粘贴、输入法、自动保存和失败草稿。[配置预检](../../../src/infra/config/config_preflight.cpp)的节点身份和摘要分别重新解析 YAML，可在有剖面证据后复用已验证语义并缩短临时树寿命；保留所有校验、限额和失败留旧。
6. **渲染/缓存基线须实测，不直接更换后端**：分别测 Qt Quick 对象、JavaScript 分配、场景图/纹理、原生堆及显卡/驱动资源，再按责任层治理。现有 [ApplicationHost](../../../app/application_host.cpp)已将场景图及图形持久化提示设为 false，并在卸载时调用 `releaseResources()`、销毁引擎；这些提示不是操作系统立即归还物理内存的保证。保持默认 RHI/GPU，不以强制软件渲染、强制垃圾回收或裁剪工作集充当修复。

## 2026-11-07 隔离真实输入与下载路径定位

本轮按新线索调查订阅更新及启动内核时的大幅增长。仅在本机标记的隔离副本使用私有输入；报告只保留匿名内存计数、行为与限制，不记录订阅名称、地址、请求头、凭据、节点/组、源文件内容、摘要或可识别的输入规模。A、B 为高增长样本，C 为通常低增长样本；用户报告 C 偶发启动或更新增长，不能将其视为不会触发的安全样本。原用户数据只读，测试副本关闭订阅/Geo 计划、系统代理和 TUN，使用独立回环端口；无关进程及官方冻结 Mihomo 二进制未改动。

已区分并处理两类实际差异：**A 的离线显示文本触发过量字体回退；A/B 的外部连接另会触发 GUI 已提交页与字体映射的大量驻留。** 前者通过字体数据库策略直接修复，后者通过有界传输进程隔离，订阅链路同时消除多余缓冲及等效配置重启。最终前台 A/C 各两次实际更新未再出现原有的大幅增长。**连接触发者仍未完整归属，C 的低概率启动异常未捕获，B 的实际 HTTP 更新没有重新验证；整体调查保持进行中。**

### 环境与基线

源码基线 `3283e02` 加本轮优化和探针；Windows x64、MSVC 14.51、Qt 6.12.0、Release，最终构建更新至 `build/dev`。保持 Qt Quick 默认 RHI/D3D11；早期下载边界实验未曝光窗口，最终三份缓存基线、A/C 实际更新、B/C 启停及公开视觉检查均确认窗口曝光。三项依次为 **专用工作集 / 总工作集 / 私有提交**，均为十进制 MB。GUI 约 20 ms 采样，辅助进程约 100 ms 采样并复用于相邻 GUI 样本；报告客户端计数包含必要传输进程，Mihomo 单列。总工作集相加会重复计算共享页，作为保守聚合；各项峰值未必发生在同一时刻，也可能遗漏更短的瞬时峰值。

### 区别一：实际显示文本与字体回退

### 区别二：外部连接触发大范围页面驻留

修正 Geo 隔离后，固定加载同一份 C 配置，只改变连接来源，不发送订阅路径或认证数据。一次性诊断程序留在忽略目录，产品不包含这些网络诊断分支：

| 未隔离连接的控制 | GUI 前→完成端点（三项 MB） | 延迟观察 |
|---|---|---|
| TLS 握手 C | 27.90 / 82.64 / 102.72 → 30.30 / 86.88 / 105.12 | 回首页 32.19 / 88.81 / 106.98 |
| TLS 握手 A | 27.87 / 82.60 / 102.58 → 100.07 / 246.99 / 103.76 | 回首页 101.86 / 248.80 / 105.55 |
| TLS 握手 B | 27.91 / 82.65 / 102.72 → 29.28 / 86.15 / 104.15 | 随后增至 103.03 / 249.97 / 106.73 |
| 原生 Winsock A，不调用 recv/WSARecv | 27.98 / 82.71 / 102.75 → 29.28 / 85.46 / 104.07 | 随后增至 102.11 / 248.35 / 105.77 |

原生实验仅发送本地生成的 ClientHello，以 FIONREAD 确认响应已排队，不读入应用；关闭连接附近可延迟增长。普通权限 PDH 的 A/C 对照也观察到延迟差异，但无缺页地址和调用栈，不能按同时活动的进程归因。

在同一诊断二进制、目标地址和固定配置下，保留 A/B 的 SNI 会触发，移除或替换为公开虚构 SNI 不触发；这是连接特征的控制实验，**生产 TLS/SNI、证书验证均保留**。另外预先提交 32 MiB、从未由应用读取的合成区域，A/B 连接后从 0 变成 8192 个驻留页，C 控制仍为 0；小型 QCore/QGui 连接探针未复现这一 GUI 行为，将连接放到小型独立传输进程后 GUI 合成页仍为 0。合成冷页支持“已有页面被读入”的判断，不识别读页者，也不是实际订阅数据规模。

为验证是否只需重构进程内下载器，另用原生 WinHTTP HEAD 替换 Qt 外部连接：未改字体策略时 GUI 28.23 / 82.76 / 136.63 → 135.41 / 289.37 / 139.17 MB，合成冷页全部驻留；启用 GDI 后也从 27.94 / 80.32 / 136.44 延迟增至 135.63 / 270.25 / 139.35 MB。两次响应为 403，仅作无订阅认证的连接控制，**不是成功订阅更新**。因此进程内更换下载 API、只修字体回退、仅减少正文/解析/重启都不足以消除这次连接触发。

未隔离连接时 A 曾连续两次实际更新后达 121.38 / 696.99 / 126.08、124.10 / 699.74 / 128.88 MB，但内容未变、同一内核 PID、没有校验进程；C 两次真实内容变化且替换内核，分别为 31.98 / 88.81 / 106.82、34.64 / 91.52 / 109.46 MB。**增长可以在不重启、不重新解析配置时发生，真实重启也不必然造成增长。** 工作集与私有提交增量明显不等，不能把全部驻留变化称为新堆分配或持续泄漏。

### 已实施的订阅与内核流程修复

- **缓冲与 304**：[订阅下载](../../../src/application/desktop_subscription.cpp)沿用按实际可读量/长度消费，普通 304 改为 64 KiB 分块验证最终地址/源摘要绑定，复用已确认摘要，省去整份缓存源缓冲及重复校验。提供者仍读取主源并刷新依赖；损坏、缺失或无绑定缓存至多一次无条件重取，失败保留旧数据。未单独量化真实 304 的收益。
- **等效配置复用**：[配置应用](../../../src/application/desktop_runtime.cpp)不再只按原文摘要决定重建。须是当前所选、已确认运行的同一条目，Ready、无恢复/清理不确定/模式或 TUN 待处理；合成后的完整有效配置摘要及全部运行偏好一致，官方可执行文件和已确认 artifact 完整性有效，才复用校验结果及现有 PID/epoch/认证文件/代理租约。新来源、历史和版本仍事务保存，不做近似比较。
- **失败保持运行**：等效提交失败只终结未提交元数据事务，保留现有内核及已保存待应用候选；manifest 已替换而日志终结失败时保留新 manifest，以 Uncertain 报告存储待恢复。真实有效配置变化仍受控停止旧内核、启动新会话、核对并提交。通用 PUT 重载尚缺完整确认/补偿及服务入口，本轮未把 restart 简单改成一次 PUT。
- **连接隔离**：[DownloadNetwork](../../../src/infra/network/download_network.cpp)与[NetworkRelay](../../../src/infra/network/network_relay.cpp)由六个外部网络管理器共享单个 `quickclash_network` 传输进程。仅其建立外部 TCP 连接；TLS、SNI、证书验证、HTTP、订阅认证及正文留在 GUI。辅助进程只处理目标主机/端口和加密字节，随机令牌经标准输入交接；最多 24 条隧道，每方向 64 KiB 队列、16 KiB CONNECT 头、10 秒连接期限，启动 5 秒、空闲 1 秒回收。Windows Job 与父进程退出通知管理寿命；显式代理保持既有选择，缺失或崩溃时请求失败，不回退 GUI 直连。

### GDI 字体策略兼容性与结案边界复核

按用户追问核对 Qt 6.12 官方文档及对应源码；本次仅源码/文档复核，未重新构建或请求真实订阅。Qt 6.8 将 Windows 默认字体后端改为 DirectWrite，同时保留受文档支持的 `fontengine=gdi` 参数。当前实现仅在 `Q_OS_WIN` 下、构造 QApplication 前设置进程默认值，尊重已有环境变量及优先级更高的 `-platform` 参数；其他平台保持自身字体实现。此做法使用 Qt 文档化的平台选项，符合其 QPA 平台适配方式，不能据此宣称 Linux/macOS 已经过原生验收。

明确的功能代价是 Qt 的 GDI 后端不支持可变字体轴（`QFont::setVariableAxis` / QML `font.variableAxes`）。当前自有产品源码未使用该功能，但不能保证所有系统回退字体呈现完全一致。字体匹配、字形度量及 hinting 的差异可能影响文字边缘、换行或省略位置；中英文和公开符号的现有检查不替代高 DPI、多屏、复杂文字及全部 Emoji 的验证，尚不能宣称存在或不存在这些环境中的呈现回归。

`fontengine=gdi` 也不表示彻底关闭 DirectWrite：Qt 6.12 的 GDI 字体数据库会在彩色字体、部分 hinting、非 1 倍设备像素比及特定字体等条件下选用 DirectWrite 字形引擎。当前没有设置 `nodirectwrite` 或 `nocolorfonts`。因此该修复改变的是字体数据库/选择路径，并非把 Qt Quick 场景图切成软件渲染；也不能承诺所有环境都不会再加载 DirectWrite 或大量字体。

官方依据：[QGuiApplication 平台参数](https://doc.qt.io/qt-6/qguiapplication.html#QGuiApplication)、[Qt 6.8 Windows 变更](https://doc.qt.io/qt-6/whatsnew68.html#windows)、[QFont 可变字体轴及 hinting](https://doc.qt.io/qt-6/qfont.html#setVariableAxis)、[Qt 平台抽象](https://doc.qt.io/qt-6/qpa.html)、[Qt 6.12 GDI 字体数据库源码](https://github.com/qt/qtbase/blob/v6.12.0/src/gui/text/windows/qwindowsfontdatabase.cpp)。

本机已复现的字体过量加载已有直接修复证据；A/C 的最终有界真实更新未再暴涨，连接隔离有缓解依据。整个问题仍不结案，直接缺口是 B 的真实更新未完成验证、C 偶发启动异常未捕获，以及真实运行的持续趋势尚未验证。底层连接触发者未归属限制根因解释和未来能否撤掉隔离进程的判断，但不单凭“必须查明 Qt/系统全部内部原因”作为无限延长验收的门槛：后续若目标环境的代表性更新、启动/停止及必要持续观察均稳定，便可按该范围关闭用户症状，底层归属单列跟踪。GDI 的其他环境呈现和无测试发行包属于兼容/发布验收边界，不是已经观察到新的内存泄漏。
