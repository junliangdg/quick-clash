### 当前源码中的优化机会

以下是 2026-11-04 最初调查时的源码快照与候选，不代表后续代码仍保持原样；按前台常驻问题优先，编辑与订阅更新峰值另列。具体实施、对照与未完成事项见下方 [首页与代理状态优化](#2026-11-04-首页与代理状态优化实施)。

1. **首页和壳层对象按需创建**：[首页](../../../qml/features/home/home_page.qml)无条件创建多张卡片，[网络工具](../../../qml/features/home/network_tools.qml)的 IP 与网站区块只以 `visible` 隐藏，隐藏不等于销毁子对象；[主窗口](../../../qml/main.qml)也预建对话框及宽/窄导航。可先用 QML 对象/内存剖面定位成本，再将禁用区块、关闭的较重弹层按需 `Loader`，并评估在保留滚动几何的前提下延后创建首屏外区域；Loader 自身有成本，只处理经测量较重的子树。**默认 IP 和网站均为开启**，因此仅为“关闭设置”添加 Loader 不会降低默认首页基线；要减少默认占用，必须测量并优化默认可见内容或首屏外创建策略。保留交互状态、动作运行时机、键盘焦点与无障碍；编辑或运行中的功能不能因滚出视口而丢失。页面切换 Loader 已存在，不应当作新优化。
2. **代理状态从全量投影改为按需**：[UiState](../../../src/presentation/ui_state.cpp)在节点、组或延迟变化后为全部节点/组重建 `proxyStates_`；[首页控件](../../../qml/features/home/home_proxy_controls.qml)即使下拉未打开也对主组所有成员生成状态、标签和描述数组。优先评估轻量变更版本/通知与当前项状态，打开列表后仅由可见 delegate 按需获取，或用稳定 ID 的角色模型。已有节点池和下拉列表可见 delegate 惰性模型，不重复实现；保留嵌套组、不同测试目标、原始选择值和无障碍语义。是否发生 QML/JS 深复制须用剖面确认，不能把 Qt 隐式共享值一律视为独立深拷贝。
3. **业务数据所有权与生命周期**：[运行通道](../../../src/application/runtime_update.h)的 `groups`、`nodes`、`delays`、`delay_details` 非页面 scoped；[UiState](../../../src/presentation/ui_state.cpp)同时持有 JSON 基线、QVariant 列表/映射和派生状态，卸载页面或窗口不等于清空这些业务数据。评估单一权威数据源、首页必需摘要及页面详情按需投影，隐藏时回收可重建的展示派生值，恢复时按需求重建，并按代次防止过期结果复活；首页仍需主组、成员及选择，不能简单清空全部数据。[controlState](../../../src/application/desktop_runtime.cpp)每次构造 `features.delayTimes`，可评估数据变化时缓存/复用；该字段属于[现有契约](../../design/03-数据模型与接口契约.md)，未经消费者及契约核对不能删除。
4. **内核控制层刷新峰值**：[DesktopRuntime](../../../src/application/desktop_features.cpp)在有代理需求时约每 5 秒刷新；[EngineSession](../../../src/infra/core/engine_session.cpp)依次读取 `/proxies` 和 `/providers/proxies`，前者的对象在后者处理期间保留并合并。先记录响应解析和发布阶段的峰值及重叠生命周期，再评估尽早投影必要字段、缩短临时结果寿命并避免无变化时重复派生。现有 `groupsPending_`/`groupsQueued_`、读取上限和 latest mailbox 已限制并发/队列，不应断言请求无限堆积；必须保留动态 provider、自动组、身份安全、失败留旧和恢复语义。此项主要面向刷新峰值，不能据此解释无内核的托盘试验；不修改 Mihomo 本体。
5. **场景化大文本和配置解析**：[编辑器](../../../qml/components/profile_editor.qml)在订阅页即构造，打开后整份文本进入 TextArea；历史 512 KiB 单行草稿有很高的提交峰值，但不能当作普通空闲前台根因。先确认当前版本真实曝光下的大文本复现，再评估弹层惰性创建及更合适的可视范围/分块编辑方案，保留全文、撤销、粘贴、输入法、自动保存和失败草稿。[配置预检](../../../src/infra/config/config_preflight.cpp)的节点身份和摘要分别重新解析 YAML，可在有剖面证据后复用已验证语义并缩短临时树寿命；保留所有校验、限额和失败留旧。
6. **渲染/缓存基线须实测，不直接更换后端**：分别测 Qt Quick 对象、JavaScript 分配、场景图/纹理、原生堆及显卡/驱动资源，再按责任层治理。现有 [ApplicationHost](../../../app/application_host.cpp)已将场景图及图形持久化提示设为 false，并在卸载时调用 `releaseResources()`、销毁引擎；这些提示不是操作系统立即归还物理内存的保证。保持默认 RHI/GPU，不以强制软件渲染、强制垃圾回收或裁剪工作集充当修复。

## 2026-11-04 首页与代理状态优化实施

### 实现范围

- [UiState](../../../src/presentation/ui_state.cpp)不再为所有节点和组常驻完整 `proxyStates_`；兼容属性仅在显式读取时生成，普通界面以版本通知按需请求当前/可见状态。首页以 `groupCount`、`nodeCount` 取计数，并仅获取当前主组；下拉框打开后由已实例化的 delegate 分别计算状态，不预建所有成员的标签、描述和测速结果。保留原始选择值、嵌套组、分组测速目标、无障碍描述及语言切换。
- 仅在资源详情展开时创建详情控件；IP 与网站区块在对应开关关闭时销毁，开启时重建且保留地址族选择。**默认 IP、网站仍开启**，因此该项不降低默认开启部分的占用。规则绑定及关闭确认对话框首次使用时创建，后续留在窗口内复用，窗口卸载时销毁；恢复窗口时重新检查待处理绑定。补测并修复进入/退出动画期间状态快速切换使规则弹窗残留的问题。
- [DesktopRuntime](../../../src/application/desktop_runtime.cpp)缓存并共享 `features.delayTimes` 现有契约投影；[ProxyLatency](../../../src/domain/proxy_latency.cpp)报告观测是否改变，重复内核轮询无变化时不重建延迟视图，在观测新增/移除、过期或时钟回拨时更新；手动测速、取消和目标切换仍及时刷新。未更改官方 Mihomo；`/proxies` 与 `/providers/proxies` 的网络响应及解析仍在，尚未完成完整单一数据源或解析峰值优化。

### 原生前台内存对照

同一 Windows 主机、MSVC Release、Qt 6.9.0，默认 RHI 的 Intel D3D11，微软雅黑、中文、1000×640、DPR 1.25。隔离页面探针创建三个组，每组引用同一批 500 或 2000 个模拟节点；默认 IP/网站开启、资源详情折叠。每个规模均在新进程中交错运行优化前和优化后四轮，`home_with_nodes` 在同步注入后等待约 2.5 秒采样端点。仅保留同一轮优化前后均为 `visible`、`isExposed` 且阶段内至少发生一次 `frameSwapped` 的配对；500 节点第 4 轮双方均无阶段帧，排除，2000 节点 4 轮均有效。总工作集可能包含共享页面，不能与其他进程的工作集简单相加。

数值依次为 **专用工作集 / 总工作集 / 私有提交**，十进制 MB；前两列为各版本端点中位数，末列为每轮配对差值的中位数，故不必等于前两列中位数直接相减：

| 模拟负载 | 有效配对 | 优化前 | 优化后 | 配对差值中位数 |
|---|---:|---:|---:|---:|
| 500 节点 | 3/4 | 123.20 / 221.56 / 161.39 | 115.59 / 215.57 / 153.79 | -6.43 / -5.17 / -6.63 |
| 2000 节点 | 4/4 | 134.85 / 233.31 / 173.60 | 118.39 / 216.60 / 157.81 | -16.17 / -16.41 / -16.49 |

2000 节点窗口对象数中位数为 1154→972（计数含 QObject 和视觉子项，不可直接换算为内存）；此综合对照不能分摊每一项的收益。测试没有 SettingsService、真实订阅、Mihomo、辅助进程或网络，且无测速数据，不能量化内核控制层缓存收益或代表完整客户端进程树；只记录短时端点，**不含同步注入峰值**，空首页未保证出现帧，也未证明长时间稳定或滚动帧性能。探针记录 Qt 曝光和帧，但未测 Win32 `IsIconic` / DWM 遮蔽。优化前可执行文件 SHA-256 `ae7dc389dffc9e230480e09fe972454b7c8c7d195f6868837b0eee15d7fba6fc`，优化后 `d17e6492e0591b3662ca2b69180fd60efd343c6100d967b0cff037d42afd32bd`；命令为 `--page-memory-test --page-memory-home-only --page-memory-nodes=<数量> --probe-language=zh-CN`。原始日志、CSV 与脚本保存在忽略的 `build/memory_optimization_20261104/comparison_final/` 及其父目录。
