日期：2026-10-25；执行者：Codex；设计基线：1.9。本次只调整设计和追踪，不修改产品代码、不运行产品构建或测试、不重新认定产品 Pass。此前运行事实见 [G2 恢复报告](20261025_g2_recovery.md)、[P2 交付](20261024_p2_implementation.md)、[协议交付](20261024_p2_protocols.md)及 [P3 日常链路](20261025_daily_use.md)。

## 1. 结论与边界

G2 应回答“Windows 本机能否完成订阅到真实代理转发，并安全停止和恢复”；G3 回答“Windows 包能否交付普通用户日常使用”。现有 G2 混入干净机器、真实系统事件、完整 GUI 异常组合及全协议验证，使部分已有实现/局部证据长期显示未完成。应缩小验收范围，不能删除错误处理、所有权或秘密保护代码，也不能用文档调整直接宣布通过。

- 保留：订阅/本地导入、候选校验和失败保留；节点/组和模式选择；官方内核后台运行/认证/所有权；系统代理、真实转发、停止/退出恢复；持久化、基本修复与秘密保护；代表性失败、崩溃和中断检查。
- 后移到 G3：干净普通用户 Windows 包验收、一次真实换网或唤醒、一次真实 GUI 整体强杀/下次启动恢复、运行会话隐藏/重建与一次实际外部代理变更核对。合并为 P3-14，复用 P2 已测底层结果，只补宿主/系统集成差异。没有干净环境时记录 Blocked，不阻塞其他功能开发；G3 仍不能据此宣称可日常交付。
- 后移到对应功能：TUN/服务 P3-04；动态资源/规则 P3-02/03；高级 DNS P3-08；高级协议 P3-09。原生多平台与 CI 仍为 P4-06，持续运行/专项按 P5-01 的实际风险选择。
- 移除统一门槛：所有协议/所有节点公网握手、所有私有订阅逐个成功、故障组合的笛卡尔积、把同一生产恢复行为在每个 UI 入口重复演示，以及全页面/多轮/长时/帧/GPU 性能矩阵。不新增一项“以后必须补齐所有组合”的总任务。必要代表性反例、已有测试和发现缺陷后的定向回归继续保留。

内存硬目标保持 Windows 客户端进程组专用工作集 ≤100,000,000 B，工作集/私有提交同时记录，内核单列。G2 复用有效的真实配置 Ready 首页 10—30 秒单场景证据，不强制把导入、更新、窗口变化和故障组合成一次性能矩阵；G3 随实际服务/页面交付抽查必要进程。已有 63,504,384 B 结果只证明当时 Ready 首页样本，不扩大为完整产品或持续运行通过。
