# 专项摘要模板

日常改动不生成 report，必要结果在 DEVLOG 简记。此模板仅供重要调查、发行核验或性能对比，优先更新已有摘要；模板本身不是完成证据。确需新建时只保留相关字段。

- 任务 ID / 工作包 / 需求 ID：
- 日期 / 执行者 / 设计版本：
- 实现版本（commit/build ID 或准确工作区补丁说明）：
- 代码/产物位置：
- 平台 / Qt / 编译器 / Mihomo / 输入摘要（按需）：
- 结论：Review / Pass / Fail / Blocked（选择一项）

## 范围与行为

本次完成内容、用户或调用者可观察的结果；哪些属于后续任务。接口/持久化变化与关联设计修改。

## 验证记录

| 命令/操作 | 环境与输入 | 预期与关键断言 | 实际结果/退出码 | 输出/证据位置 |
|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 未运行 | 待填写 |

仅说明适用的失败、取消/迟到、重启恢复与清理；未运行项不能当通过。不虚构测试文件。原始输出放 build/ 或 CI artifacts（默认14天），报告保存关键结果及不可变 Actions 运行链接；需长期复核的少量证据人工精选至 reports/evidence/。

## 资源与限制

资源变化/测量范围、三项内存指标、同环境基线与缓存/生命周期影响；无需性能专项的改动给出理由。客户端持续追求小内存占用，不设固定MB硬门槛。遗留缺陷及其是否阻断本任务/阶段；不能用未实现的占位值证明达标。

## 追踪更新

任务状态、相关验收 ID（Pass/Fail/NotRun/Stale）、可能失效的旧结果及下一任务。阶段未整体通过时明确保留。
