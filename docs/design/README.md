## 1. 已确定的项目方向

2026-10-25补充：P3-11交付Windows日常订阅更新/选中自动应用与失败补偿、名称筛选及可运行包，实际结果见[报告](../progress/reports/20261025_daily_use.md)。新订阅默认6小时更新/自动应用，旧条目维持手动，07明确策略/边界；完整G3与普通用户干净环境仍按台账后续核对。

**QuickClash 的 P3/G3 目标是 Windows 可日常使用；Windows 开发同时保持多平台架构与功能边界，当前先检查静态兼容，Linux/macOS 在 P4 逐平台原生覆盖，远期增加 Android/iOS 形成五平台。** 静态检查、原生构建、真实系统验收分别记录，不互相替代；当前不创建移动端工程。以 FlClash 为主要 UI/交互参考，采用 C++20 + Qt Quick，Windows 客户端进程组专用工作集目标 ≤100 MB，Mihomo 单列。应用显示名 QuickClash，内部程序/命名空间名 quickclash；自有源码目录/文件采用小写下划线，现代 C++/Qt 所有权和工具约定见 [编码规范](../development/cpp_style.md)。

本次范围、任务与当前静态缺口见 [G3 方案调整记录](../progress/reports/20261025_g3_windows_plan.md)；P3-12 是方案交付，P3-13 是待完成的静态兼容收敛任务，不据此将 G3 或其他平台标为通过。

**先交付最小订阅—代理闭环：添加完整 Mihomo YAML 订阅或本地文件 → 校验/激活 → 启动官方预编译 Mihomo → 选择代理组/节点与模式 → 开启系统代理 → 验证真实转发 → 停止并恢复。** 内核固定来自 [MetaCubeX/mihomo 官方 Releases](https://github.com/MetaCubeX/mihomo/releases)，按 tag/OS/arch/CPU/摘要锁定，不自行编译或修改。安装包携带已验证程序，首次启动可离线使用。

**实施就绪结论：设计已足够启动工程、契约验证与 UI 原型；Windows MVP 的功能和失败路径可按 18 拆分实现。** P0/G0 仍须锁定工具链/官方内核资产、验证关键 API 与离线配置测试，不把设计约定当成实测结果。P2 交付用户态离线验证包并通过 19 的 16 项 MVP 验收；provider/外部文件配置暂不属于 P2，内嵌配置及 Geo/DNS 的具体支持边界见 07 的 1.1。

**UI采用导航＋页面：宽度≥600逻辑像素时左侧完整展示八模块；小于600时底部仅仪表盘、代理、设置，窗口最小360×480。** 次级页面经首页/设置进入，同一注册表、路由及业务服务跨布局复用；Android/iOS平台工程仍仅预留边界。英文源文案经Qt翻译管理，中文/英文按系统首选序匹配，无匹配用英文。页面参考[用户提供的FlClash截图](../reference/README.md)，采用柔和扁平圆角贴片，内置浅色/深色主题及跟随系统。MVP见01；首页见08；模块契约见02—04/15；截图映射见17；网络与资源验收见19。

100 MB 指 100,000,000 字节，约 95.37 MiB。预算包含客户端宿主、Qt/QML、业务、托盘、必要辅助进程与常驻权限服务；不得通过拆进程规避。Windows 以专用工作集验收，另存总工作集和私有提交；Linux/macOS 口径到 P4 冻结，GPU 单列。常用页面与支持负载中的正常操作峰值都需要验收，详见 [13 性能预算](13-性能预算与基准方案.md)。

首版采用一个 Qt 客户端 + 外置 Mihomo，权限需要时使用受限服务。界面具备可见、隐藏和卸载三态；业务和内核会话不依赖 QML 生命周期。独立 UI 进程、原生托盘和自定义场景图只在测量表明必要时引入。

用户给出的现有占用观察：Mihomo 一般不足 100 MB、Verge Rev WebView 约 200—300 MB、FlClash 常见约 600 MB（500—700 MB）。这些数值需按版本、页面和进程/内存口径复测，本文不把它们写成已验证结果，不承诺固定下降百分比。

## 5. 使用与限制

1.8 明确 G3 只验收 Windows 日常使用，三平台/五平台为未来逐步覆盖路线；当前新增跨平台静态兼容任务，核对依赖、接口、构建条件、能力、路径、导航/翻译和生命周期。未运行的原生/系统检查保持 NotRun，已识别 Windows 耦合需修正，静态结果不等于平台支持。必要 Windows 恢复、干净环境与 TUN/服务实测仍保留。

1.4 将应用定名为 QuickClash，固定 C++20/Qt 编码实践与小写下划线源码命名，增加格式/静态分析配置与命名检查，并建立随代码维护的任务/阶段/MVP/证据台账。旧合并文档文件名为保持已有链接可达而保留，内容标题与应用身份使用 QuickClash。

文档给出实现方向、默认策略、失败处理与验收条件。工具链、官方内核和参考 UI 的实施基线见 [基线矩阵](../baseline/release_matrix.json) 与 [参考台账](../reference/reference_manifest.md)，当前完成状态及实测证据见 [开发进度入口](../progress/README.md)。支持范围、断点和分项预算需要按阶段验证；Windows客户端进程组专用工作集100 MB目标已确定，总工作集/私有提交另记，不能在实现时自行放宽。

1.3 复审补齐了停机选择与运行确认/空历史、组合启动失败补偿、监听/初始设置、订阅最小管理与重启持久化、配置子集/离线 Geo/DNS、租约幂等与端口迁移、Windows Job/唤醒/修复、P2 离线包和依赖拆分。G2 验收由 8 项扩展为 16 项。当前不存在需要用户补充才能开始 P0 的产品决策；版本和行为验证是工程交付任务，见 18/2.1。

API 表为常见 Mihomo 控制接口规划，P0/P2 需对锁定版本核验请求体、流协议与能力。FlClash 页面参考需在 P0 固定 commit 并截图，本文的断点和组件映射不冒充其源码实现。移动平台的运行容器、签名和分发只保留边界。

用户截图 UI-REF-20261023-01 已归档，可用于首页直接对照，但其仓库版本和示例数据未核验。深色主题及移动精选入口/嵌入策略为本项目设计，不冒称截图已展示这些能力。桌面窄窗底栏在P2-18实现，移动平台工程仍不实现。P2-19加入英文源文案与中英文系统自动匹配/英文回退。

各分册均有验收条件，16 汇总需求，18 提供执行模板。测试名称是计划，不表示测试已经存在或运行通过。本次未创建客户端代码和性能结果。

1.1 已补齐八类能力、最小转发闭环、官方内核资产、事务/权限/恢复与资源验收。1.2 将 UI 统一为桌面左侧导航＋右侧页面，明确模块注册/导航投影/嵌入复用及移动底栏边界，补全双主题圆角贴片与用户参考图映射。IP 为可选功能；TUN、完整诊断与自动更新不阻塞 MVP。
