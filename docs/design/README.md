# Qt Quick + Mihomo 客户端完整设计文档

版本：1.0；日期：2026-10-23；文档性质：架构、功能与实施设计；状态：待实现与实测。分册是编辑源，合并版由分册生成。

## 1. 已确定的项目方向

**近期交付 Windows、Linux、macOS 桌面客户端，以 FlClash 为主要 UI/交互参考，采用 C++20 + Qt Quick 实现；桌面客户端层总内存目标 ≤100 MB，Mihomo 单独统计。Android、iOS 仅预留架构边界。**

100 MB 指 100,000,000 字节，约 95.37 MiB。预算包含客户端宿主、Qt/QML、业务、托盘、必要辅助进程与常驻权限服务；不得通过拆进程规避。Windows、Linux、macOS 使用固定且分别说明的平台口径；GPU 单独列明。常用页面与支持负载中的正常操作峰值都需要验收，详见 [13 性能预算](13-性能预算与基准方案.md)。

首版采用一个 Qt 客户端 + 外置 Mihomo，权限需要时使用受限服务。界面具备可见、隐藏和卸载三态；业务和内核会话不依赖 QML 生命周期。独立 UI 进程、原生托盘和自定义场景图只在测量表明必要时引入。

用户给出的现有占用观察：Mihomo 一般不足 100 MB、Verge Rev WebView 约 200—300 MB、FlClash 常见约 600 MB（500—700 MB）。这些数值需按版本、页面和进程/内存口径复测，本文不把它们写成已验证结果，不承诺固定下降百分比。

## 5. 使用与限制

文档已经给出实现方向、默认策略、失败处理与验收条件，但尚未锁定 Qt/内核/参考 UI 的具体版本，也没有实际资源数据。版本、断点和分项预算需要按阶段验证；总内存目标 100 MB 已确定，不能在实现时自行放宽。

API 表为常见 Mihomo 控制接口规划，P0/P2 需对锁定版本核验请求体、流协议与能力。FlClash 页面参考需在 P0 固定 commit 并截图，本文的断点和组件映射不冒充其源码实现。移动平台的运行容器、签名和分发只保留边界。

各分册均有验收条件，16 汇总需求，18 提供执行模板。测试名称是计划，不表示测试已经存在或运行通过。本次未创建客户端代码和性能结果。
