版本：1.19；日期：2026-11-04；文档性质：目标、架构、技术契约、设计决策与验收标准。19个分册是编辑源，合并版由脚本生成。

**文档职责：设计目录只描述应当如何工作、为什么这样设计以及如何验收，不承载开发流水账。** 不在设计正文追加日期式修改记录、实现批次、当前任务状态、构建/测试结果或性能实测数字。修改方案时直接更新对应章节；当前任务和风险见[任务台账](../progress/TASKS.md)，发布核验见[检查清单](../progress/CHECKLISTS.md)，复杂经过见[接续日志](../progress/DEVLOG.md)，重要历史证据见[报告索引](../progress/reports/README.md)。设计版本/日期与参考资料标识仅用于基线识别，不代表产品完成状态。

## 1. 已确定的项目方向

**QuickClash 是跨平台 Mihomo 客户端：当前 P3/G3 在 Windows 上交付可日常使用版本，Linux/macOS 在 P4 逐平台原生覆盖，Android/iOS 作为远期宿主仅保留边界。** 当前只有 Windows 具备原生实现与验收证据；跨平台目标不等于其他平台已支持。静态检查、原生构建、真实系统验收分别记录，不互相替代；当前不创建移动端工程。UI 统一采用极简桌面工具风，以 C++20 + Qt Quick 实现，保持默认RHI/GPU渲染。客户端以小内存占用为目标，不设跨机器统一的固定MB硬门槛，Mihomo 单列。应用显示名 QuickClash，内部程序/命名空间名 quickclash；自有源码目录/文件采用小写下划线，现代 C++/Qt 所有权和工具约定见 [编码规范](../development/cpp_style.md)。

**先交付最小订阅—代理闭环：添加完整 Mihomo YAML 订阅或本地文件 → 校验/激活 → 启动官方预编译 Mihomo → 选择代理组/节点与模式 → 开启系统代理 → 验证真实转发 → 停止并恢复。** 内核固定来自 [MetaCubeX/mihomo 官方 Releases](https://github.com/MetaCubeX/mihomo/releases)，按 tag/OS/arch/CPU/摘要锁定，不自行编译或修改。安装包携带已验证程序，首次启动可离线使用。

当前 Windows 实现的功能、依赖和失败路径按18拆分；P0/G0负责锁定工具链/官方内核资产、验证关键API与离线配置测试。P2交付用户态离线验证包，按19的16项MVP条件验收；provider/外部文件配置不属于P2，内嵌配置及固定Geo/内部DNS的边界见07/1.1。G3验收Windows日常使用、普通用户干净环境及必要OS/GUI宿主行为，其他平台后续逐步覆盖。

**UI采用导航＋页面并按窗口宽度自适应：宽度≥1000逻辑像素为图标文字侧栏，600—999为八模块图标轨，小于600为仪表盘、代理、订阅、设置四个底部图标入口；默认1000×640、最小360×480。** 次级页面经设置/摘要进入，同一注册表、路由及业务服务跨布局复用；窄窗底栏只说明窗口布局适配，不构成移动OS支持，Android/iOS平台工程仍仅预留边界。英文源文案经Qt翻译管理，中文/英文按系统首选序匹配，无匹配用英文。界面以中性灰、小圆角、轻边框和少量蓝紫强调统一全部控件与页面，内置完整Light/Dark及跟随系统。统一规范见17，[概念预览](../reference/quickclash_minimal_preview.html)可离线浏览；MVP见01，首页见08，模块契约见02—04/15，网络与资源验收见19。

客户端统计包含宿主、Qt/QML、业务、托盘、必要辅助进程与常驻权限服务；不得通过拆进程掩盖成本。Windows 同时记录专用工作集、总工作集和私有提交；Linux/macOS 口径到 P4 冻结，GPU 单列。Qt版本、驱动、字体、DPI和负载差异须记录；常用页面与支持负载中的稳态、峰值及有界生命周期按同环境基线评价，详见 [13 性能预算](13-性能预算与基准方案.md)。

首版采用一个 Qt 客户端 + 外置 Mihomo，权限需要时使用受限服务；服务按安装时授权、客户端不可申报的受信客户端根识别调用方，便携副本与安装版各自经一次授权安装即可共用一个服务。界面具备可见、隐藏和卸载三态；业务和内核会话不依赖 QML 生命周期。独立 UI 进程、原生托盘和自定义场景图只在测量表明必要时引入。

与其他客户端比较时，固定版本、OS、页面、负载及进程/内存口径后独立测量；视觉风格或技术栈不直接证明性能收益，不承诺未经测量的下降百分比。

## 5. 使用与限制

设计给出目标、架构、默认策略、失败处理和验收标准，不记录开发批次、当前任务状态或实际测试结果。工具链与官方内核见[基线矩阵](../baseline/release_matrix.json)，UI契约以[17统一规范](17-界面参考与QtQuick落地.md)为准；[界面参考说明](../reference/README.md)区分Qt截图、HTML示意及其来源范围。当前完成状态及实测证据统一从[开发进度入口](../progress/README.md)查询。

G2验收Windows本机最小闭环，首次关键失败、所有权/租约、秘密保护和真实转发都是必要条件。干净普通用户环境、真实换网或唤醒及GUI宿主补证归P3-14/G3；Windows TUN/服务、八页面日常能力与共享静态兼容同属G3。其他平台的原生构建和真实功能按后续阶段分别验收，静态检查不能代替平台支持声明。

验证按受影响功能和单场景短测选取；全协议握手、故障穷举及重复性能矩阵不作为统一门槛。客户端以小内存占用为目标，不设固定MB门槛；记录三项内存指标，以同环境比较和有界生命周期核对资源变化。IP为可选功能，TUN、完整诊断和自动更新不阻塞MVP。

API表为Mihomo控制接口规划，P0/P2须对锁定版本核验请求体、流协议与能力。概念预览只展示布局与交互，所有数据均为演示，不请求网络、不改系统，不作为产品实现、默认配置或资源验收证据。理念参考不引入外部UI框架、字体或素材依赖。

各分册定义验收条件，16汇总需求，18给出工作包/依赖与评审模板。测试名称是验收规划，不表示测试已存在或通过。移动平台只预留运行容器、权限、签名和分发边界。合并版沿用既有文件名以保持链接兼容，内容标题与应用身份使用QuickClash。
