# 07 订阅、配置来源与资源更新

覆盖 F03，并与 F02、F08 衔接。订阅负责获取候选；配置服务负责验证和应用，二者不能混成“下载后直接覆盖运行文件”。

## 1. 支持输入

新建HTTP/HTTPS订阅时名称可空，手填名称优先；留空则读取最终成功响应的profile-title（UTF-8原文或base64:编码），其次Content-Disposition的filename*（UTF-8/ISO-8859-1及百分号解码）、filename。文件名移除路径与.yaml/.yml后缀；控制/格式字符清除并限制80字符，缺失或无效时使用本地化通用名称。每个元数据头最多4096字节，不从URL查询或节点名称猜测订阅名；更新和替换来源保留已有名称。

订阅管理按稳定ID提供单个地址框：默认隐藏已保存URL，可显示、复制或进入编辑；编辑按需读取原始地址并全选，修改在内存中作为草稿，保存前不改变来源。本地配置可从同一入口添加地址。读取结果匹配弹窗请求令牌，读取失败就近提示。关闭弹窗清除明文，页面离开或窗口隐藏时隐藏明文；未保存草稿在关闭、退出或切页前提供保存、放弃和继续编辑。保存进行中请求关闭或退出时等待结果；失败留在编辑界面，避免退出中断操作或丢失输入。复制保留完整原URL/查询，复制已显示地址时保留显示状态；复制内容留在系统剪贴板。URL不进入列表、运行快照、日志或备份。请求头不回显，更换时默认不沿用旧自定义头，可在地址编辑区展开并重新填写。

支持本地 Mihomo YAML/JSON、HTTP/HTTPS 订阅，以及官方内核可解析的 URI/Base64 节点列表。请求默认发送 User-Agent clash.meta/1.19.33 QuickClash/0.1.0 和 YAML 优先的 Accept；显式请求头覆盖默认值。去除地址首尾空白，保持查询参数和签名，不盲加 flag/target 参数，不使用第三方转换服务。节点列表包装为受管 file provider 和默认选择组，节点内容始终由所选官方内核解析。

下载后按正文识别，不单凭 Content-Type；合法配置即使标为 text/html 也继续预检。空正文、HTML 登录页和错误 JSON 拒绝；格式识别通过后仍须完成官方校验，不能把下载成功当作导入成功。

### 1.1 配置支持边界

配置兼容性以当前选中的官方 Mihomo 为准。客户端不维护另一套协议、传输、DNS、策略组或规则类型白名单；AnyTLS、VLESS 等节点和嵌套选项保留给内核判断，内核忽略的无关生成器字段不再被客户端提前拒绝。内核升级仍遵循固定来源、版本和摘要管理。

| 内容 | 技术契约 |
|---|---|
| 协议、传输、策略组、路由规则、DNS、sniffer 等 | 有界解析后交给所选官方内核校验；缺少 proxies/proxy-groups/rules 可规范化为空列表。内核已移除的功能也不能因旧客户端允许而通过 |
| YAML | 单文档，拒绝重复键；支持锚点、别名与合并键，独立展开后受深度、事件、字节预算约束，循环和放大输入拒绝 |
| 提供者 | 支持 inline、显式 HTTP/HTTPS 和本地 file；YAML/text/MRS、URI/Base64 代理正文由官方内核消费。需要筛选、覆盖、复杂依赖或原生格式时自动保留运行时图，避免有损展开 |
| 宿主设置 | 应用设置管理端口、回环绑定、controller、secret、TUN、外部 UI、额外监听/tunnels、LAN、Geo 和系统时钟写入。原文保留，被覆盖项记录，不允许订阅改变高权限服务边界 |
| 外部文件 | provider 文件在普通用户上下文打开并复制到摘要派生路径；相对路径以本地导入文件目录解析。远端订阅缺少本地基目录时，相对文件引用明确失败；其他证书等文件需要可受管化资源，不能凭内核支持就绕过隔离边界读取宿主文件 |
| 资源预算 | 配置解压后 16 MiB、深度 32、事件 100000；静态节点 5000、组 500、规则 20000；provider 最多 32、单项 4 MiB、下载合计 16 MiB。达到预算给出错误并保留旧配置 |

桌面官方 `-t` 校验使用当前受管内核程序的独立普通用户进程及临时工作目录，不依赖 Windows AppContainer 注册；每阶段10秒超时，失败保留确认版本。原生 provider 正文另在无数据监听和健康检查的临时内核中，以已准备的 file vehicle 加载并通过固定 provider 更新端点确认，防止 `-t` 只检查配置结构而遗漏坏正文。此处独立进程/目录用于事务与生命周期隔离，不构成OS权限或强制断网沙箱。临时目录与进程随完成、失败、取消回收；原配置未确认前不改变运行内核。权限服务对已批准配置另做的校验随服务身份运行（Windows为SYSTEM），不宣称普通用户或OS权限隔离；其输入仅限固定命令预检后的受管字节。

Geo 由应用管理并关闭内核自动更新，订阅 geox-url 被移除并提示可能的匹配差异。Hysteria2 的 mport 别名规范化为 ports，显式 ports 优先。节点有界标量 x- 厂商元数据保留于原文、从有效配置移除并提示。默认预览仅公开必要名称、类型及组成员，其他节点字段、provider 和未分类子树遮蔽，新增协议凭据也不得泄露。

内核加载、实际节点连接及所有远端节点可用性分别验收；兼容性不等于提供方服务可达。

订阅编辑包含名称、URL、更新间隔、自动更新、自动应用、下载路径策略、必要请求头。完整 URL/请求头通常含凭据，不显示在列表、通知和默认诊断中。

页面以订阅管理为主，标题区提供添加订阅入口；空列表同样保留此入口。添加弹窗支持HTTP/HTTPS地址与本地配置或节点列表、可选名称及下载路径。点击提交后立即进入处理中模态状态，禁用关闭按钮、Esc及点击外部关闭，后台首次状态到达前也保持该约束；隐藏窗口不关闭仍在处理的弹窗，恢复后继续显示结果。下载和安全校验均有等待上限，失败或超时解除忙碌状态、保留当前输入并在弹窗显示可重试错误，允许关闭及重新打开；实际新增条目且操作结束无错误后关闭。若条目已保存但后续操作报错，提示已添加并禁用重复导入；闲置时关闭、离页或隐藏清除地址。管理弹窗将当前地址、更新计划、自动应用和下载路径置于常用区域，原文及覆盖编辑和历史版本放入高级设置。地址修改后点击“保存并更新”执行下载、校验、保存及适用时应用；未保存即关闭弹窗或窗口/退出时提供保存、放弃、继续编辑。保存期间请求关闭或退出会等待结果；操作按ID和令牌匹配，失败保留输入及旧来源，已保存但应用失败分别报告。仅有效配置变化才会重启内核并中断连接。管理区使用响应式小卡片，显示名称、选中状态、更新时间、套餐用量/总量/到期、计划和更新结果；更新失败与待应用候选可同时显示，各自提供重试或应用操作。点击卡片即应用对应订阅，后台内核及代理分组同步切换；首个有效导入自动选中，后续导入保留当前选择。删除当前条目需确认并恢复网络、清空选择；失败保留旧状态。

MVP 先交付添加/编辑来源、手动更新、查看校验结果及明确激活；计划调度、用量告警后续补齐。入口可称“订阅”，其详情中包含配置原文/覆盖，用户不必理解 runtime artifact 才能启动代理。首次添加成功后允许用户继续“激活并启动”，下载完成本身不等于已启用。

## 2. 下载状态机

Idle → Scheduled → Downloading → CandidateStored → Validating → Ready；网络失败进入 Backoff，内容失败进入 Rejected。激活进入配置事务，不属于下载状态。

每个 subscriptionId 最多一个下载；再次手动更新可附着当前任务或取消后重启。删除订阅先取消任务并失效 generation，迟到响应不得重新创建已删除配置。

## 3. 网络策略

订阅主源采用单操作串行、默认直连、15秒传输/20秒整链截止和16MiB解压后累计正文上限，并配合定时调度/失败退避。用户可显式选择受管代理或Auto；安全跳转、路径回退与条件缓存均属于同一次操作，预算不逐跳重置。provider资源下载保留其独立限制，不自动继承主源跳转或认证策略。

| 项目 | 策略 |
|---|---|
| 下载路由 | MVP 默认 Direct；RunningProxy/Auto 需用户显式选择，不继承全局系统代理或控制 API 的回环策略 |
| Auto | 直连优先；允许时失败后通过已就绪内核尝试一次，并记录路径 |
| 并发 | P3沿用单操作串行，主源/provider共享下载额度；有实际收益证据后再评估最多2个，不作为G3前置 |
| 超时 | P3保留15秒传输/20秒总截止；路径回退与重定向共用同一总截止，不逐跳重置 |
| 重定向 | 最多 5 次；跨 origin 不转发敏感请求头 |
| 大小 | 解压后默认上限 16 MiB，流式计数防压缩膨胀 |
| 条件请求 | ETag、Last-Modified与最终URL保存在DPAPI来源信封中，以URL/请求头摘要及sourceHash绑定来源版本；只向匹配最终URL发送，304只复用已核hash原文，缺失/损坏则单次无条件重取 |
| 重试 | 保留现有失败退避，不另加即时重试循环；显式Auto最多一次路径回退，401/403、格式错误不因回退高频重试 |

不自动接受 HTTPS 降级到 HTTP；显式配置兼容源时另行处理。URL 不允许 file/执行型 scheme；本地网络 HTTP/HTTPS 订阅可能是用户实际需求，按明确来源使用，而非把所有私网地址一概拒绝。

RunningProxy 使用明确指定的受管 HTTP/SOCKS 代理，内核不可用时返回可解释错误，不形成启动前必须先通过自身代理下载配置的循环。首次启动始终可用本地配置或 Direct 获取。

未显式指定代理的HTTPS连接使用同目录`quickclash_network`传输进程，经随机回环端口的认证CONNECT隧道连接目标；这不改变Direct的路由语义，仍受系统路由/TUN影响。TLS握手、证书校验、SNI、HTTP、重定向、来源认证和正文处理留在客户端，传输进程只接收目标主机/端口并转发TLS字节，不接收订阅路径或来源请求头。显式RunningProxy/其他指定代理继续使用对应入口。

同一业务运行时的订阅、资源更新、网站/IP测试等网络管理器共享一个传输进程，按在途请求计数；零请求后约1秒退出，新请求可重新创建。启动截止5秒，辅助进程缺失或崩溃明确使在途请求失败，不退回GUI外连。Windows用Job与父进程退出通知约束寿命，客户端退出或被终止后不得遗留传输进程。随机认证凭据经标准输入传递，不放命令行、日志或持久化；服务只绑定IPv4回环，最多24个隧道、CONNECT头16KiB、连接截止10秒，每方向读/写队列分别限64KiB，取消立即关闭隧道。该进程始终计入客户端三项内存统计，不能视作内核。

最多5次重定向及Auto回退均受总截止、解压后大小和操作代次约束；受管代理捕获当前会话epoch。跨origin移除全部自定义来源头，后续跳回也不恢复；不自动降级TLS，不保存或发送Cookie。Auto仅对没有HTTP响应的连接/DNS/传输网络错误回退一次，TLS、401/403及内容错误不回退。失败保留旧候选/确认版本。304遇到原文缺失/不匹配时清除验证器后进行一次无条件获取，再次304必须失败。

普通无provider订阅的304用64KiB分块校验已绑定原文，复用已确认摘要，不整份读入缓存或在完成阶段重复校验；provider主源仍读取并核对原文以继续刷新依赖。二者保留相同的最终地址/摘要绑定、损坏重取及失败留旧规则。

## 4. 候选提交与激活

下载先写 temporary 文件，检查状态码、大小、内容、来源与 generation，计算摘要后提交候选原文。Content-Type 是提示，真正以结构校验决定，HTML 登录页面不能当 YAML 成功。

非活动配置更新：保存新 source 候选并校验，当前内核不变。新订阅默认每6小时更新并自动应用选中条目的变化；旧条目缺失策略字段时维持手动策略，可在订阅页开启。用户可关闭定时更新后的自动应用或选择手动/1/6/12/24小时周期；主动点击更新或保存地址对当前选中条目自动应用，不受该开关影响。后端允许15分钟至7天。校验失败保留旧源与确认版本；通过校验后保存新候选，应用失败则尝试补偿回旧确认会话，保留候选并标记待应用。原文候选与确认运行版本分别记录，不能将下载成功显示为已应用。

同一订阅条目修改地址与普通更新一样保留用户自建策略组定义；订阅来源自身提供的策略组以新原文为准。自建组依赖的父组或提供者缺失、名称与新原文冲突时，拒绝不兼容候选并保留旧来源和自建组，不能静默删除用户定义。节点选择按名称与身份核验后恢复；无匹配候选时保留组定义并安全兜底。显式删除条目时，其本地自建组随条目移除，其他条目不受影响；历史回退按对应版本恢复定义。

内容摘要相同且无待应用候选时只刷新下载记录，不重启核心。原文改变但仅涉及注释、格式或会被规范化移除的元数据，合成后的完整有效配置仍与当前运行一致时，按06/4.1精确复用会话并提交新的来源/历史；不因原文摘要改变就无条件重启或重复创建校验进程。已有候选待应用时，主动更新仍尝试应用；定时更新遵从自动应用开关。每次更新结束记录并展示结果类别：已是最新、已更新且配置等效（内核未重启）、已更新并应用（区分同进程重载与内核重启）、已保存待应用，以及定时更新因连接活跃而等待应用；同时在应用日志追加不含地址与名称的一行说明。结果类别随订阅条目保存，等待状态只存在于运行内存，并随重启、停止、切换、删除或手动更新取消，不写入条目。定时更新应用到当前所选且内核Ready的订阅，且合成配置与运行会话不等效、将触发配置重载或受控重启时，先只读查询内核连接：无连接、查询失败或解析失败都继续应用；存在活跃连接则保存候选、保持待应用并定期复查，空闲后按待应用重试流程应用，累计等待30分钟后仍然应用，不无限推迟。主动更新、保存地址、“立即应用”及配置等效的复用不受此约束。待应用状态提供明确的应用或选择入口；下载失败与先前的待应用候选、应用失败可同时展示，成功确认候选后清除相应的应用失败提示。模式/端口修改仅处理已确认配置，不顺带应用新下载候选，也不能清除其待应用标记。停机时应用仅更新下次选择，不自动启动核心或打开系统代理。

provider主源先持久化并释放下载正文；串行暂存和展开完成后，只将最终有界快照交给预检。普通同内容更新分块复核已有文件，不读出第二份原文；provider仍重新获取并比较展开快照，变化按自动应用事务处理，同内容不重启。可信语义通过06/3的worker私有上下文转移，取消/代次失效不能复用；未接管候选与provider临时文件分别清理。

展开快照模式下，应用是资源下载和缓存的唯一写者；每项资源保存受限不可变正文、SHA-256、来源URL摘要及更新时间，目录只引用应用生成的路径。单项刷新读取已核hash的保存主源，只下载所选资源，其他资源须按key/来源摘要/正文摘要匹配缓存后复用；缓存缺失或损坏明确失败并提示完整订阅更新修复，不暗中扩大为全部下载。展开/预检/官方校验全部成功后才提交新缓存引用与快照，同内容复用不可变资源，坏更新清理候选并保留当前会话；变化仍遵循自动应用偏好和06的配置重载/重启事务。当前/保留历史引用的缓存不得清理，UI不接收内部路径或URL摘要。快照刷新与内核动态provider端点更新分开展示，前者重载配置，后者直接更新资源。

重复RULE-SET通过重读保持原顺序，同时限制整次展开累计扫描128MiB/200000事件（含初次与重扫，单文档100000、初次合计100000仍保留），防空规则集/大注释重复引用放大工作量。显式标签按标量/序列/映射种类白名单检查，不放行任意标准命名空间标签。可信立即应用同时分块复核原文和快照。

订阅更新与用户编辑同时发生时，候选另存，禁止直接覆盖草稿。选择状态恢复由 [08](08-总览与代理组.md) 的名称/成员存在性规则处理，不把旧 YAML 中的选择重新写回原文。

### 4.1 最小管理操作与持久化

MVP 包含添加、重命名、替换 URL/请求头、手动更新、选择/应用、删除，并能保存至少两个配置后切换；不要求先完成覆盖编辑器。修改 URL/请求头时增加 sourceGeneration、清除旧 ETag/Last-Modified、取消旧下载；旧运行 artifact 与旧可用源保留到新候选确认，编辑成功不代表下载或应用成功。名称修改不触发内核重启。

删除非活动配置时取消下载并使 generation 失效，再原子移除索引；删除当前运行或下次所选配置时，用户选择“先切换到指定已验证配置”或“停止并删除”，默认取消。切换/停止及租约处理未成功不得删除；无其他配置时只允许停止并删除，成功后回到未配置首页。同一 manifest 更新中替换或清空指向被删对象的 ConfigSelection、activeRevision/lastGoodRevision 及对应偏好/资源引用，不能留下悬空指针；无历史引用后才可清理文件/秘密，未完成恢复事务的引用不得删除。保留策略中的历史 artifact 仍按引用规则清理，不立即递归删目录。

应用重启恢复列表、所选版本、脱敏来源与确认历史，按每条策略恢复计划；新下载是否替换选择由自动应用开关决定。停止时激活按06只提交下次选择；运行时同条目等效更新复用会话，其他更新/切换优先走06的同进程重载事务，进程/控制器/Geo条件变化才重启，失败尝试恢复旧确认配置。配置重载仍可能中断已有连接；定时更新遇活跃连接会先推迟，也可关闭自动应用以手动安排切换。

## 5. 调度和电源变化

调度器使用一个single-shot定时器管理全部计划，保存UTC下次时间；最长15分钟重新核对时钟，到期等待最短1秒。所有更新串行，与配置/模式操作互斥，忙时5秒后核对。重开和换网/唤醒合并核对只执行一次过期更新，不补发遗漏的每个周期。该业务定时器在托盘/页面卸载时保留。进程退出取消下载和定时器；停止/取消不能因迟到响应重启核心。手动更新立即执行，操作中重复命令被拒绝。

失败保存结果和最后尝试时间。网络失败下次以5/10/20/40/60分钟退避，最大1小时；401/403或内容/应用失败至少等待1小时且不短于正常周期。成功恢复正常周期。没有即时循环重试，不强制探测外网；离线识别、计量网络设置、随机抖动属于扩展网络适配。失败显示在订阅页/错误记录，URL/头不得出现在这些结果中。

扩展网络策略为离线暂停、恢复后带抖动执行，按受控并发队列处理。基础串行退避与完整离线/电源策略分别验收。

如果用户设置“计量网络不自动更新”，平台能力不可得时显示限制并遵从保守策略。托盘/卸载状态仍可进行低频业务计划更新；它与页面统计停止不冲突。

## 6. 用量与到期信息

解析来源响应中的订阅用量头时，字段单位和格式按约定处理。未知/格式错误显示“来源未提供”，不推断为无限或零。用量不等同本机流量累计，多设备使用和提供方统计延迟需在帮助说明中解释。

元数据随响应保存最后采集时间；本机流量图由内核遥测提供，二者不混算。首页与订阅卡片的配置更新时间和用量采集时间按本地时间显示至分钟：二者可解析且显示结果相同时只展示更新时间，不同时或任一未知时分别展示，避免掩盖旧采样；本地配置仅展示更新时间。显示临近到期/流量告警不导致高频轮询。

用量头最多1024字节，upload/download/total为非负十进制整数，expire为Unix秒；重复、带符号、溢出或不可表示日期的字段分别视为未知。原始计数以十进制字符串保存，上传与下载均有效时才计算已用量；total为0或缺失不推断无限套餐。已用量达到90%提示剩余不超过10%，达到总量提示耗尽；到期前7天（含边界）提示临近到期，到期时提示已过期。采集时间独立保存；200响应或带用量头的304刷新元数据，缺失字段不沿用旧值；不带用量头的304保留旧采样及采集时间。配置编辑、回退及提供者重建也可能改变配置更新时间，不能将其视为用量采集时间。重开时从已保存元数据计算状态，不将展示告警写回为来源数据。本地到期边界复用订阅调度器刷新，不新增下载或高频定时器。

## 7. 规则集、Geo 数据与提供者

P2的静态Geo随包策略见1.1；动态资源分为P3-19的provider/RULE-SET和P3-20的Geo。应用管理订阅与导入快照，运行时provider由内核管理。两种模式必须明确区分：

- 导入快照：应用在受限staging串行获取proxy-provider/rule-provider并展开为有界不可变配置；记录来源身份/内容摘要和采集时间，更新属于重新获取候选及正常配置事务。界面显示“更新导入资源/重新应用”，不宣称实时provider刷新或保留内核独立更新语义。
- 运行时provider：配置保留受管逻辑引用，内核独占对应可写缓存；刷新调用锁定API，应用不得并发写同一文件。RULE-SET依赖、远端失败/旧缓存、动态节点身份和服务固定命令分别验收。仅实现导入快照不能作为运行时provider能力通过；不支持的字段和较弱的历史回退保证必须明确说明。

简单 YAML/text 资源默认采用导入快照，用户可显式切换为运行时模式；涉及筛选、覆盖、复杂依赖、file/MRS 或原生代理正文时自动保留运行时语义。inline 无需下载。HTTP/HTTPS 和本地文件先由应用受限暂存，原始 path 替换为种类、名称、来源、格式、行为派生的生成路径；规范化配置保存结构化 fallback 或原始正文的有界 Base64 封装。MRS 和原生代理正文直接由官方内核读取。interval 缺省 0，显式周期和健康检查选项由官方内核校验；后台写入仅由内核执行。

运行时缓存独立于不可变资源存储，最多32项、每项4MiB（总正文至多128MiB），内核是运行期间唯一写者。重载在独立版本目录暂存候选并复制身份匹配的HTTP缓存，不改当前版本；普通模式事务结束保留活动版本，服务保留活动与上一补偿版本，单次请求可暂增一个候选。仅清理不再活动的生成版本，正常停止后保存最后缓存供下次启动；拒绝链接及未知目录/文件，不得清扫任意用户路径。导入下载仍受合计16MiB约束。内核网络栈遵循冻结版本自身的TLS、重定向及解析策略；应用暂存最多跟随5次安全跳转，禁止HTTPS降级并在跨源时移除自定义头；YAML规则集采用多行payload标准形式，规则条目错误可能被内核忽略，客户端读回实际计数。

单项运行时刷新使用PUT /providers/{proxies|rules}/{encodedName}，服务IPC只接纳当前配置白名单中的kind/name，不接受URL、路径或额外字段。刷新不重启内核、不修改配置快照，完成后读回成员及规则计数；失败保留内核当前状态。超时表示结果未确认，不自动重试；停止、换会话和释放需求后拒绝迟到数据。API节点描述不包含完整端点指纹，动态成员只能显式选择，不持久化或自动恢复；静态/动态同名也按未验证身份处理，提供者读回失败时不以部分结果恢复选择。

运行时历史回退恢复逻辑配置及导入fallback，不冻结之后的远端更新和可写缓存；启动可能继续采用当前内核缓存。两种备份范围都从不可变导入 fallback 导出离线配置，普通 YAML/text 可展开，原生正文保留受管 file 与原始字节；源范围另保留原文及覆盖，恢复后不自动获取远端资源；不读取正在写入的内核缓存，也不承诺保存最近热更新的成员。动态内容须重新获取才能进入新的不可变版本。

Geo资源使用明确的应用更新任务或交由内核机制管理，指定唯一写者。

Geo更新先经GitHub API解析官方meta-rules-dat的release分支完整提交，再从该不可变提交下载两库，记录revision、摘要及时间；禁止连续请求可变latest导致跨批混用。下载路径显式Direct或CurrentProxy，后者要求已确认内核，失败不隐式换路。默认手动，可选每日/每周单次低频计划；离线或失败按同一周期重试，忙时延后，唤醒只合并一次。计划只下载和官方双库校验，将不可变引用保存在待应用记录，不改变运行配置或中断连接；用户确认后重验并走正常事务。待应用引用纳入垃圾回收保护，重开后仍可确认。Geo状态展示当前快照和上次成功下载；HTTPS/提交固定及本地摘要不等于上游签名认证。普通/TUN共用同一事务与资源；更新不安装服务、不隐式请求权限。

P3 Geo 由应用资源更新任务作为唯一写者，采用版本化不可变文件和配置事务切换引用；关闭同一资源的内核自动更新。锁定版本不支持关闭时不提供应用并发更新，显式改用内核管理并记录较弱的历史回滚保证。provider 保持内核唯一写者及独立缓存目录，服务模式的刷新经固定 IPC。不可变资源引用经 06 的配置事务提交；动态内容变化只更新资源状态索引/generation，不另行改写配置提交权威。指纹不可靠的节点不跨内容变化自动恢复。

手动Geo下载使用[专用存储写入器](../../src/infra/storage/geo_resource_writer.h)，共享仓库路径/ACL边界，在受限临时目录逐块写入并同步SHA-256；网络缓冲和单次读取最多64KiB，累计32MiB+1拒绝。成功HTTP200/当前generation、非空后，复核临时文件长度与流式摘要，再经禁止直接写回退的原子文件提交至摘要命名不可变路径；失败/取消清理临时文件，迟到不能提交。两个资源及官方隔离校验通过前不切换快照，旧资源/引用保留；中途已提交的无引用新资源按独立保留策略管理，不在下载事务中直接回收。Geo专用32MiB提交不扩大普通配置16MiB策略。HTTPS与本地摘要保证下载/落盘一致性，不提供额外的上游签名真实性保证。此路径是手动资源更新，不在每次普通订阅更新时执行。

摘要路径已存在时，必须流式复核已保存文件的长度和完整摘要后复用；损坏目标拒绝且不覆盖。两项引用均未变化时显示未变化，不重启内核或轮换历史。下载及官方隔离校验期间可取消，取消使整轮代次失效、释放暂存和校验进程，保留当前内核；应用开始后只允许正常事务补偿。回退保存上一对引用，空对象明确表示随包离线资源；显式恢复随包资源同样校验两库并经事务应用。无论当前配置是否含Geo规则，更新、回退和离线恢复均使用有效的双库探测配置进行官方校验。失败不得将新旧两库混合激活。

全局“更新资源”需列出会更新哪些内容，分别显示结果。资源下载成功不自动宣称配置已应用。外部引用路径在配置校验时受管化或明确拒绝，不依靠任意相对路径逃逸工作目录。

## 8. 验收与阶段

SUB-01 HTML/超大/压缩膨胀响应被拒绝，旧配置保留；SUB-02 304 但本地源缺失时重新获取而非报成功；SUB-03 跨域重定向无认证头泄漏；SUB-04 删除后迟到响应不复活；SUB-05 休眠一晚后不补发数十次更新；SUB-06 用户草稿与新候选并存；SUB-07 代理不可用时首个配置仍能导入；SUB-08 使用信息未知不显示零；SUB-09 自动应用失败回退最后可用版本。

订阅更新保留条目的用户覆盖项，原文、展开快照及覆盖共同组成编辑基线；用户草稿的旧基线引用独立保留。更新不会重写草稿或自动合并文本；冲突按06处理，只有明确重新载入才丢弃旧草稿。手动历史回退校验保存的内容，不重新获取远端provider，不恢复历史来源凭据或更新计划。

P2 完成 MVP 订阅添加、限额下载、手动更新/激活与失败保留旧值；P3 完成计划/用量/资源管理，P4 完成网络/电源适配，P5 验证长时间调度与恢复。
内存边界：Geo校验/复制按64KiB流式进行，摘要通过后原子提交；YAML预算扫描器先释放再分配Node图。无provider且源hash及保存字节均相同的下载复用已校验源，更新凭据/时间/套餐信息，保留待应用/自动应用策略；provider即使主源未变仍抓取并校验。新内容须重新执行schema与合成，官方隔离校验仅可按06/4.1的精确条件复用，实际有效配置变化仍完整校验。

只读元数据（格式/provider发现、节点身份、分组摘要、Geo需求）以有界事件扫描提取必要字段，不为全部规则建立Node图；跳过字段仍检查重复键、别名、多文档与深度/事件预算。schema预检及官方-t仍完整执行。

订阅列表独立按内容变化发布完整JSON通道；GUI稳定ID模型按profile id增删/移动和精确roles更新，不reset整表。仅请求的行/卡片转换为展示值，兼容profiles属性只在显式读取时展开；生产订阅页与首页不读取该整份属性。投递仍需线性比对完整JSON，不是worker逐字段补丁协议。

订阅页采用ListView复用可变高度行，每行严格最多3张卡片，按可用宽度580/900断点显示1/2/3列；不使用一个巨大delegate包住所有卡片。每行高度取可见卡片内容最大值，长名称、翻译和用量文字换行，导入表单作为可滚动头部保留。卡片/按钮动作捕获当前稳定ID；背景选择低于独立按钮，键盘可聚焦按钮及上下移动虚拟行。管理/删除/回滚对话框由页面持有，管理ID变化按单条查询刷新，删除后安全关闭，不依附可复用delegate。

对话框显式锚定窗口Overlay而非可滚动内容坐标，避免大订阅内容尺寸影响弹层位置。宿主关闭/自动卸载共用真实托盘恢复能力检查；析构先进入退出状态，避免销毁期间回调重建。

空的第二/第三slot不创建卡片内容，只由Loader占位；单列不额外实例化两张隐藏卡片。列变化只改变分组/可见卡片，不改变业务ID或重新执行订阅动作。

主源允许显式HTTP；HTTPS跳转不得降级，跨源后不再发送自定义认证头。应用设置和资源预算仍按受管边界执行。

预检规则采用有界标量序列检查长度及数量，输出使用 YAML emitter 转义；策略引用和语义交给官方内核，其余字段完整保留。重复键和多文档拒绝，别名独立有界展开；规则不必建立完整 Node 图。
文件及网络读取按实际长度/可读字节分配；策略上限用于拒绝超额输入，不直接当作每次读取的预分配量，避免小配置持有16MiB缓冲跨越异步操作。

provider正文串行写入[受控暂存](../../src/infra/storage/provider_stage.h)，复用仓库安全路径及当前用户/SYSTEM ACL；每块≤64KiB，单项4MiB、累计16MiB、最多32项，超额哨兵不落盘。保留TLS验证、最多5次HTTP/HTTPS安全跳转（禁止HTTPS降级、循环及跨源自定义头转发）、10秒传输/15秒整链截止；停止先失效代次、释放事务，弱回调不复活旧文件，RAII清理临时文件。强杀清理、实际ACL与删除失败行为须有独立验收证据。

[文件展开器](../../src/infra/config/config_provider_stream.cpp)事件读取主源规则/YAML payload，文本逐行，不建立全部规则Node图或保留所有provider规则向量。重复RULE-SET按原位置重读文件，保留classical/domain/ipcidr、no-resolve、重复引用及代理组use原序。受限节点/组小图：节点累计5000、组500、成员引用累计100000、结构字段累计4MiB；主源及各provider初次扫描累计100000事件，每文档深度32/事件100000、标量8192字节；展开累计20000规则/16MiB在追加时检查。重复键/多文档/非法标签拒绝，别名先有界展开；嵌套规则依赖自动保留原生provider图，完整结构检查及官方隔离校验保留。缓冲API仅兼容适配，生产走文件；预检仍需一份≤16MiB完整字节，不属于零拷贝。
